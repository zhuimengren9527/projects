# 347. 前 K 个高频元素 (Top K Frequent Elements)

## 1. 题目背景
在一个给定的整数数组中，找出出现频率最高的 $k$ 个元素。这是数据挖掘和自然语言处理（NLP）中“高频词统计”的基础逻辑。

## 2. 方案演进与对比

我分别采用了两种不同的算法来实现，并进行了性能对比：

### 方案一：哈希表 + 全排序 (solution_v1.py)
* **实现逻辑**：
    1. 使用字典 `.get()` 方法统计词频。
    2. 使用 `sorted()` 函数对所有唯一的键进行全排序。
* **时间复杂度**：$O(N \log N)$
* **评价**：逻辑最直观，代码简洁。当数据量 $N$ 较小时，这是最推荐的写法。

### 方案二：哈希表 + 小顶堆 (solution_v2_heap.py)
* **实现逻辑**：
    1. 同样先进行词频统计。
    2. 维护一个大小为 $k$ 的**小顶堆**（Min-Heap）。
    3. 遍历频率字典，若堆满则弹出最小元素，确保堆内始终保留频率最高的 $k$ 个元素。
* **时间复杂度**：$O(N \log K)$
* **评价**：**性能优化版**。当 $N$（总数据量）极大而 $k$（提取数量）较小时，该方案比全排序更快，且更节省内存。



## 3. 核心知识点复盘
* **Python 技巧**：
    * 熟练运用 `dict.get(n, 0)` 处理统计初值。
    * 掌握了 `heapq` 模块的 `heappush` 和 `heappop` 操作。
* **算法思维**：
    * 理解了为什么在找“最大 $k$ 个”时，反而要用“小顶堆”（为了方便弹出最小的，留下大的）。
* **机器学习关联**：
    * 此逻辑常用于 **特征筛选（Feature Selection）**：在成千上万个特征中，只保留权重最高的前 $k$ 个特征，以降低模型复杂度。
