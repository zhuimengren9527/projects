# Git 远程同步：从 HTTPS 切换到 SSH 的全流程指南

> **写在前面**：配置 SSH 就像是给这台电脑办了一张 GitHub 的“内部通行证”。它不用去挤 HTTPS 的公共大门，而是带着藏在硬盘里的“实体钥匙”，走 22 号专用地道直接进入仓库。

---

### 🌟 一、 原理解析：为什么要换通道？

| 特性 | HTTPS 连接 (旧大路) | SSH 连接 (新地道) |
| :--- | :--- | :--- |
| **协议端口** | 443 端口 (网页流量) | 22 端口 (加密隧道) |
| **公司环境** | 极易被防火墙“安检”或拦截 | 通常被视为运维流量，拦截较少 |
| **身份验证** | 每次可能需要账号密码 | **一劳永逸**，凭本地钥匙秒进 |
| **报错表现** | `Connection Refused` 或 `Timeout` | 只要钥匙对得上，连接极稳 |

#### 什么是 Ed25519？
它是目前最顶级的“制锁工艺”。比老式 RSA 算法更短、更安全、计算速度更快，是程序员换电脑时的首选。

---

### 🛠️ 二、 准备工作：清理障碍 (针对公司网络)

在配钥匙前，必须先让电脑“忘掉”之前的错误路径：

1. **清空 Hosts 文件**：
   - 路径：`C:\Windows\System32\drivers\etc\hosts`
   - **操作**：删掉或用 `#` 注释掉所有包含 `github.com` 的行。
2. **刷新 DNS 缓存**：
   - 终端输入：`ipconfig /flushdns`
   - **目的**：不再让电脑按照旧 IP 瞎撞南墙。

---

### 🛠️ 三、 实操三板斧 (换电脑必做)

#### 第 1 步：打钥匙 (在本地电脑生成身份凭证)
打开 VS Code 终端，运行以下命令（一路狂按 **回车** 到底，不要输入任何字符）：

```bash
# -t ed25519: 使用顶级加密工艺
# -C: 备注你的 GitHub 身份
ssh-keygen -t ed25519 -C "zhuimengren9527"
    * **注：**看到屏幕出现了一个“艺术字符方块”时，说明钥匙打好了
```
* ***代码拆解：**
    1. **ssh-keygen —— 召唤“锁匠”**
    - 这是命令的主体。keygen 是 Key Generator（密钥生成器）的缩写。它告诉电脑：“我现在需要一套新的安全凭证，请帮我生成一下。”
    2. **-t ed25519 —— 选择“制锁工艺”**
    - `-t`：代表 Type（类型）。
    - `ed25519`：这是指定的工艺名称。
    - `老工艺 (RSA)`：就像那种巨大的十字锁，虽然稳，但钥匙又大又笨，计算起来慢。
    - `新工艺 (Ed25519)`：目前最现代的加密方式。它的特点是钥匙极短，但安全性极高，且验证速度极快。在公司这种复杂的网络环境下，它更不容易出错。
    3. **-C "zhuimengren9527" —— 刻上“钥匙挂坠”**
    - `-C`：代表 Comment（注释）。
    - `"zhuimengren9527"`：这只是一个标签。
    它就像是在钥匙扣上挂了一个小牌子，上面写着你的名字。它的作用：当你以后在 GitHub 网页上管理一大堆钥匙时，看到这个名字就知道：“哦，这是我那把专属钥匙。”它不参与加密，纯粹是为了好认。

    4. **🔑 执行后的“成品”：一对钥匙**
    当你按下回车后，系统实际上会生成两个文件：

    - `id_ed25519 (私钥)：`这是真钥匙。它会被锁在你自己电脑的“保险柜”里（~/.ssh/ 文件夹）,绝对不能给别人看，更不能删掉。
    - `id_ed25519.pub (公钥)`：这是锁头（.pub 代表 Public，公开的）。它的形状和你的钥匙完全匹配。我们要把它贴到 GitHub 上，相当于在 GitHub 的大门上挂上一把只有你能开的锁。

### 第 2 步：配锁头（将公钥形状告诉GitHub）

1. **获取钥匙内容：**
    - 在终端输入`cat ~/.ssh/id_ed25519.pub`。
2. **复制内容：**
    - 完整复制那串以`ssh-ed25519`开头的内容
3. **上传GitHub:**
    - 登录GitHub -> Setting -> SSH and GPG keys -> New SSH key。
    - Title:填这台电脑的名字（如：Company-Laptop）。
    - key:把复制的内容粘贴并保存。

### 第 3 步：改地道（最关键：让项目切换协议）

必须在projects文件夹根目录下运行，把原来的HTTPS连接升级为SSH：
```python
# 1. 验证地道是否通畅
# 看到 Hi zhuimengren9527! You've successfully authenticated 就稳了
ssh -T git@github.com

# 2. 彻底修改远程仓库地址 (重点步骤！)
# 原理：把远程地址从 https:// 格式改成 git@github.com: 格式
git remote set-url origin git@github.com:zhuimengren9527/projects.git

# 3. 检查是否修改成功
# 应该看到两个以 git@github.com 开头的地址
git remote -v

# 4. 尝试同步
git pull
```
